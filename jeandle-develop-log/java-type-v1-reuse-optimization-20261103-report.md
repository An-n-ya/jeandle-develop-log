## 性能结论

相对本轮优化前 V2，**全部 10 个场景显著改善**。完整 opt 的成本降低 **3.87%–37.57%**，与 V1 的差距缩小到 **4.39%–10.32%**；两项跨上下文微基准分别降低 **81.02%** 和 **70.99%**。百分比为同轮配对成本变化，不是不同实验中位数相除。

新版保留了 V2 的 oracle 失效、PHI 环、definedness 与预算边界。在这轮测试中已缩小与 V1 的差距；无关修改场景仍需清空 oracle 相关结果，差距尚未解决。V1 + null-edge 仍然更快，不能宣称已全面追平旧缓存。

## 代码改动

1. 在 Facts 中增加 `(Value, Block)` 的累计路径结果表。先复用整段前缀，避免仅命中边事实后仍遍历、合并整段 CFG。
2. 仅在 StableOracleEpoch、单值查询（Argument 或入口块 select）、完整函数块数不超过 facts budget 时启用。查询一旦遇到未切断的 CFG 环，不发布受污染的路径结果；复杂 PHI/其他转发查询和紧预算维持原边缓存/单次查询路径。
3. 入口块 select 直接复用 Base 求解结果。合法 SSA 中，其操作数定义点均在入口块或为参数/常量；这些位置没有额外的 CFG 路径事实，重复递归不会增加类型信息。非入口块 select 的定义点细化保留。
4. 路径结果与逐边缓存不重复填充；原始 guard/null 计算仍正确计数，PathHits/PathMisses 单独记录。完成的单次查询 memo 槽由共享路径结果接管。
5. 基本块数量只在 CFG epoch 内计算一次。LLVM 的 `Function::size()` 会遍历链表；非 CFG/oracle 通知只保留该结构计数，仍丢弃全部路径、边和 Final 结果。CFG 变化或 clear 则重算资格。

涉及的生产代码为 [JavaTypeCache.h](artifacts/v1-reuse-optimization-20261103/after/JavaTypeCache.h)、[JavaTypeCache.cpp](artifacts/v1-reuse-optimization-20261103/after/JavaTypeCache.cpp) 和 [JavaType.cpp](artifacts/v1-reuse-optimization-20261103/after/JavaType.cpp)。[设计说明](artifacts/v1-reuse-optimization-20261103/after/JeandleJavaTypePathReuse.md) 记录了复用边界。

## 正确性与性能审计

- **84 个单元测试、63 个相关 Pass 回归测试全部通过**。新增五项测试覆盖路径前缀复用/预算变化/oracle epoch、不可约环拒绝发布、入口 select 避免重复递归、非入口 select 保留细化、CFG 扩大后重新校验预算。
- 原有统计测试仅更新入口 select 少一次操作数查询导致的计数；recover-shallow 由每查询两个边条目改为一个累计路径条目，其他结果检查保留。
- 每版本每 native 场景逐次与新建 DT/AC/LVI 的完整原始 JavaType 对比，要求 class 22；V1 不得跳过验证。20 组诊断/输入审计通过。
- 四版本 opt 输出 IR 逐字节一致，每版本 verification 与 diagnostic IR 也逐字节一致。全部输入哈希与前一轮实验一致。
- 三个对照复用上一轮的原二进制，开始核对版本/哈希；所有二进制在计时结束后再核对。计时关闭统计和差分验证。
- 固定 CPU 8 / SMT 兄弟 9，不更改系统服务或 governor，移除 LD_LIBRARY_PATH。每场景 3 轮预热 + 15 对 V1/V1 A/A，再 3 轮预热 + 31 轮四版本随机串行交错，种子 20261103。
- native 分版本校准批次数至约 360ms CPU。4000 次 bootstrap 的 95% CI 必须完全越过对应 A/A 绝对变化 P95，且所有正式样本至少 200ms，才判改善/回退。
- 最终轮 **1540 个正式样本，最短 CPU 246.55 ms**，SUCCESS 与 audit.json 齐全。本机再次从原始采样独立复核全部 10 组成本中位数、60 组配对变化、6 份源码快照哈希及驱动哈希，均一致。第一版未完成的采样单独保留，没有拼入最终轮。
