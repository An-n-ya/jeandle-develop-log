# 架构



## 当前设计：

​	设计了一个总的 cache 类`JavaTypeCache`，内含三个 cache 管理基础类型、路径事实和最终类型三层缓存，并且改造了跟其相关连的所有函数。原函数内置了相关的共享 cache，且cache集中在一次查询阶段（单次调用），因此通过外部构造 总Cache对象，将总Cache对象传入，然后将函数内部自己创建的 cache对象替换为传入的总对象成员的引用。

​	原函数内原有的 cache 相关结构如下：其中 BaseTypes 和 Processed 都在 JavaTypeQueryContext 中定义。每次都会新建这个对象，然后传入函数以及后续递归使用。

| 内容                               | 原始函数中是否存在 | 生命周期           |
| ---------------------------------- | ------------------ | ------------------ |
| 基础类型缓存 `BaseTypes`           | 有                 | 单次顶层查询       |
| 路径事实缓存及计算状态 `Processed` | 有                 | 单次顶层查询       |
| 完整查询结果缓存 `FinalTypes`      | 没有               | 后来的缓存引擎新增 |

​	因此当前设计针对这种情况做了如下调整：

- 将 `BaseTypes` 改为外部缓存成员的引用，使基础类型结果能够跨查询复用。

- 新增 `PathFacts`，保存可跨查询复用的路径事实。`Processed` 仍保留在单次查询中，用于记录递归状态和局部结果。

- 新增 `FinalTypes`，缓存完整查询结果，并允许 PHI incoming 查询读取已有结果。

- 新增截断、循环标记及命中统计，用于控制缓存发布和辅助验证；递归栈与预算仍在每次查询时重新创建。

- 由 `JavaTypeAnalysisResult` 持有总 Cache，并接入 FAM。当前 TCE 和 CHA 已通过该分析结果查询类型，原始引擎保留用于关闭缓存及对照验证。

​	当前依旧有尚未完成的工作如下：

- 细粒度失效尚未实现，当前修改通知仍采用全量清空。

- 预算截断和 PHI 环场景可能跳过严格相等校验，相关正确性测试仍需补充。

- 其他消费者尚未全部迁移，真实 JVM 验证及性能收益评估尚未完成。

### 具体

​	该部分按照如下结构分别展开叙述：缓存组织、缓存使用、缓存更新、缓存失效。

#### 缓存定义

总缓存类 `JavaTypeCache` 包含三个成员：

- `BaseTypes`：以 `Value *` 为键，保存基础类型。
- `PathFacts`：以 `(Value *, BasicBlock *)` 为键，保存路径约束。
- `FinalTypes`：以 `(Value *, BasicBlock *)` 为键，保存完整查询结果。

缓存归属于单个 Function 的 `JavaTypeAnalysisResult`。每次查询创建的 `CachedJavaTypeQueryContext` 引用这些共享缓存，同时持有本次查询的递归状态、预算和截断标记。

#### 缓存使用

无上下文时查询 `BaseTypes`；有上下文时优先查询 `FinalTypes`，未命中再计算值维度与路径事实，过程中复用 `BaseTypes` 和 `PathFacts`。

PHI incoming 可以读取已有 `FinalTypes`，命中后仍需合入当前边的约束。关闭缓存时直接调用原始引擎；开启 verification 时额外重算并检查结果。

#### 缓存更新

缓存采用按需填充方式。基础类型允许缓存独立根查询结果及未受 PHI 环影响的子结果；路径事实在未发生相关截断时发布到 `PathFacts`，否则仅保留在本次查询中。

`FinalTypes` 只发布未发生 facts/PHI 预算截断的顶层结果，不保存递归中的 PHI 局部结果。完整计算出的 Unknown 也允许缓存。PHI 环标记本身不阻止顶层结果发布，但可能使该次查询跳过严格相等校验。

#### 缓存失效

当前通过 `clear()` 全量清空三个缓存，累计统计保留。`invalidate(Value &)` 暂时也采用同样策略。

Pass 内修改相关 IR 后，需要在下一次查询前清理缓存并维护 DT/LVI。Pass 结束时，如果没有保留该分析，或 DT/LVI 依赖失效，FAM 会丢弃整个 Result。当前 TCE 在批量折叠后清理，CHA 在相关改写路径中清理缓存并更新依赖。

#### 阶段和循环标记问题

当前三个标记：

| 标记             | 触发原因                                                  | 当前处理                                     |
| ---------------- | --------------------------------------------------------- | -------------------------------------------- |
| `FactsTruncated` | 路径事实预算耗尽，或遇到普通回边规则无法切断的 CFG 递归环 | 停止后续共享路径事实发布，不发布本次最终类型 |
| `PhiTruncated`   | PHI 求值预算耗尽                                          | 不发布本次最终类型                           |
| `PhiCycleHit`    | PHI 递归中遇到当前栈上的 PHI，跳过循环 incoming           | 不单独禁止顶层结果发布，但影响严格相等校验   |
